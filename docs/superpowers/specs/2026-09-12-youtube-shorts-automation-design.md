# 유튜브 쇼츠 매일 1건 자동화 — 설계

작성일 2026-09-12

## 1. 목표

AI 관련 이슈·도구·업무 자동화를 다루는 한국어 유튜브 쇼츠를 **매일 1편, 사람 개입 없이** 생성하고 예약 공개한다. 주제 선정은 조회수·구독 전환을 최대화하는 방향으로 자동화한다.

### 성공 기준

| 항목 | 기준 |
|---|---|
| 파이프라인 | `daily.py` 1회 실행으로 수집→업로드까지 무인 완주 |
| 산출물 | 1080×1920 / 30fps / 목표 초수 ±15% mp4 |
| 자막 | 실제 음성 타이밍과 동기화 (오차 0.3초 이내) |
| 한글 렌더링 | 두부(□) 0건 |
| 비용 | 편당 대본 LLM 비용 외 0원 |
| 중복 | 최근 30일 발행 주제와 중복 0건 |

조회수·구독자 수치는 성공 기준에 넣지 않는다. 외부 요인이 지배하므로 코드로 보장할 수 없다. 대신 **터질 확률을 높이는 구조**를 성공 기준으로 삼는다.

## 2. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 언어 | 한국어 전용 | 국내 시장 집중 |
| 타깃 | AI 쓰는 직장인 (기획·마케팅·사무직) | 개발자 대비 국내 모수 10배 이상 |

## 4. 아키텍처

단계별 독립 스크립트가 날짜 폴더에 산출물을 남긴다. 어느 단계가 깨지든 그 단계부터 재실행할 수 있다.

```
유뷰트 쇼츠 자동화/
├── config.yaml            요일별 포맷, 업로드 시각, 점수 가중치, 브랜드
├── .env                   ANTHROPIC_API_KEY
├── config.py              .env + config.yaml 로더
├── daily.py               오케스트레이터 (스케줄러가 호출하는 유일한 진입점)
├── steps/
│   ├── collect.py         이슈 수집 + 실측 점수화 → topics.json
│   ├── script.py          Anthropic API → script.json
│   ├── voice.py           edge-tts → narration.mp3 + timings.json
│   ├── render.py          ffmpeg → short.mp4
│   └── upload.py          YouTube API → 예약 공개
├── assets/
│   ├── fonts/             Pretendard Black (한글 자막용)
│   └── bg/                배경 그라디언트 / 루프 클립
├── history.jsonl          발행 이력 (중복 차단)
├── seeds.yaml             콜드 스타트용 에버그린 주제 풀
└── out/2026-09-12/
    ├── topics.json  script.json  narration.mp3
    ├── timings.json  subs.ass  short.mp4  result.json
```

데이터 흐름은 단방향이다. 각 단계는 앞 단계의 JSON만 읽고 다음 JSON을 쓴다. 단계 간 공유 상태는 없다.

## 5. 주제 선정 — 이 프로젝트의 핵심

### 5.1 조회수와 구독은 다른 메커니즘이다

조회수는 완시청률·공유에서, 구독은 "다음 편도 보고 싶다"는 정체성에서 나온다. 한 편이 둘 다 노리면 둘 다 놓친다. 주 7편을 **유입 5편 + 전환 2편**으로 나눈다.

- 유입편 — 짧고, 단일 메시지, 즉시 이해. 완시청률 최적화
- 전환편 — 시리즈 구성, 다음 편 예고. 구독 전환 최적화

### 5.2 요일별 포맷

| 요일 | 포맷 | 길이 | 성격 |
|---|---|---|---|
| 월·수·금 | AI 이슈 속보 (직장인 관점) | 25초 | 유입 |
| 화·목 | 바로 쓰는 AI 업무 꿀팁 | 40초 | 유입 |
| 토·일 | 업무 자동화 사례 (시리즈) | 45초 | 전환 |

### 5.3 바이럴 앵글 7종

이슈를 그대로 쓰지 않고 아래 앵글 중 하나로 변환한다.

| 앵글 | 예시 | 주 지표 | 제약 |
|---|---|---|---|
| 손실 회피 | "이거 아직 유료로 쓰세요?" | 저장률 | — |
| 즉시 실행 | "복붙하면 끝나는 프롬프트" | 저장·공유 | — |
| 국내 한정 | "한국어로 쓰면 성능 떨어지는 이유" | 국내 채널의 해자 | — |
| 비교 판정 | "A랑 B 실제로 시켜봤습니다" | 댓글 → 노출 | 실제 검증 결과만 |
| 숫자 충격 | "월 3만원이 0원이 됩니다" | 클릭률 | 출처 필수 |
| 반전 폭로 | 통념 뒤집기 | 완시청률 | — |
| 직업 위협 | "이 업무 6개월 뒤 사라집니다" | 조회수 최상 | **주 1회 상한** |

직업 위협형은 조회수가 가장 잘 나오지만 반복하면 채널이 공포 소구로 굳어 구독 전환이 떨어진다. `config.yaml` 의 `angle_weekly_cap` 으로 코드에서 강제한다.

### 5.4 점수화 — 랜덤 제거

측정 가능한 값만 사용한다. 총점 100점 만점 + 패널티.

| 축 | 배점 | 산출 |
|---|---|---|
| 검색 수요 | 0~30 | YouTube Search API로 키워드 검색, 상위 10개 조회수 중앙값을 로그 스케일로 정규화 |
| 경쟁 공백 | 0~25 | 상위 10개 중 최근 90일 업로드 비율. 낮을수록 고점 (수요는 있는데 최신 영상이 없음 = 기회) |
| 신선도 | 0~20 | 이슈 발생 후 경과 시간. 24시간 이내 만점, 7일 0점 |
| 앵글 적합도 | 0~15 | §5.3 중 적용 가능한 앵글 수 |
| 타깃 적합도 | 0~10 | 직장인 키워드 사전 매칭 (보고서, 엑셀, 회의록, 기획, 마케팅 등) |
| 중복 패널티 | −40 | `history.jsonl` 최근 30일 제목과 키워드 자카드 유사도 0.4 초과 시 |

YouTube Search API는 호출당 100유닛, 일일 한도 10000이다. 후보 10건 평가 시 1000유닛으로 업로드(1600유닛)와 합쳐도 여유가 있다.

임베딩 유사도는 쓰지 않는다. 중복 판정에는 키워드 겹침으로 충분하고 의존성만 늘어난다.

### 5.5 수집 소스

키가 필요 없는 무료 소스만 쓴다.

- Hacker News Algolia `search_by_date` (`points>50`, 48시간 이내)
- Google News RSS — `인공지능`, `AI 업무`, `챗GPT` 쿼리
- 전자신문 · ZDNet Korea RSS (국내 맥락)
- GitHub 급상승 리포지터리 (도구 발굴용)

한 소스가 실패해도 나머지로 진행한다. 전부 실패하면 `seeds.yaml` 로 폴백한다.

### 5.6 콜드 스타트

**신규 채널이 속보를 올리면 뜨지 않는다.** 채널 권위가 없어 알고리즘이 밀어주지 않기 때문이다. 초기 30편은 검색 수요가 꾸준한 에버그린으로 간다.

- 0~30편 — `seeds.yaml` 에버그린 80% + 이슈 20%
- 31편 이후 — 에버그린 40% + 이슈 60%

`history.jsonl` 의 누적 편수로 자동 전환한다.

### 5.7 이슈 → 주제 변환

수집된 원시 이슈를 Anthropic API에 넘겨 앵글을 매핑한다. 템플릿 문자열 조합은 쓰지 않는다. 출력은 후보 5건이며, 각 후보에 §5.4 점수를 매겨 1위를 선택한다.

## 6. 대본 생성

Anthropic API 1회 호출. 요일 포맷별 프롬프트 템플릿을 사용한다.

```json
{
  "title": "60자 이내, 앞 25자에 검색 키워드",
  "hook": "첫 2초 자막, 12자 이내",
  "segments": [{ "narration": "읽을 문장", "caption": "화면 자막" }],
  "loop_line": "마지막 1.5초, 다시 보게 만드는 문장",
  "description": "설명란",
  "tags": ["최대 15개"],
  "sources": ["근거 URL"]
}
```

핵심 제약 세 가지를 프롬프트에 명시한다.

1. **나레이션과 화면 자막을 분리한다.** 귀로 듣는 문장과 눈으로 읽는 자막의 적정 길이가 다르다. 자막은 12자 이내로 끊는다.
2. **겪지 않은 경험을 1인칭으로 서술하지 않는다.** "제가 해봤더니" 금지. "공개된 벤치마크에 따르면" 형태로 쓴다.
3. **수치·인용은 `sources` 에 URL을 남긴다.** 근거 없는 수치는 생성하지 않는다.

목표 초수 × 한국어 TTS 분당 330자로 목표 글자 수를 역산해 프롬프트에 넣는다.

## 7. 음성 · 렌더 · 업로드

### 7.1 음성

`edge-tts`, 한국어 뉴럴 음성, 속도 +12%. 쇼츠는 빠른 발화가 이탈률에 유리하다. `WordBoundary` 이벤트로 단어 단위 타이밍을 받아 `timings.json` 에 저장한다. 이것이 자막 동기화의 근거가 된다.

### 7.2 렌더

1080×1920 / 30fps. `timings.json` 으로 `.ass` 자막을 생성해 ffmpeg `subtitles` 필터로 번인한다.

- 자막 안전 영역 y 620~1250. 하단은 쇼츠 UI가 가리고 상단은 제목이 겹친다
- 폰트는 `assets/fonts/` 동봉본을 1순위, `malgunbd.ttf` 를 폴백으로 쓴다. **둘 다 실패하면 예외로 중단한다.** 기본 폰트로 조용히 넘어가면 두부가 찍힌 영상이 그대로 업로드된다
- 배경은 그라디언트에 느린 줌. 0~2초 훅은 대형 텍스트
- BGM은 넣지 않는다. 저작권 검토 없이 넣을 만한 음원이 없다

렌더가 이 파이프라인에서 가장 깨지기 쉬운 지점이다. ffmpeg 필터 체인과 한글 폰트 두 곳 모두 실패 사례가 확인됐다.

### 7.3 업로드

`videos.insert` 로 `privacyStatus=private` + `publishAt=당일 업로드 시각(RFC3339)`. 예약 공개는 반드시 private으로 올려야 동작한다.

할당량은 업로드 1600유닛 + 검색 1000유닛으로 일일 한도 10000 내에서 여유롭다.

### 7.4 스케줄

Windows 작업 스케줄러가 매일 08:00에 `daily.py` 를 호출하고, 그날 18:00 예약 공개로 올린다. 작업 스케줄러의 "가장 최근 예약이 누락된 경우 가능한 한 빨리 시작" 옵션을 켜 PC가 꺼져 있던 날을 보정한다.

각 단계는 1회 재시도하고, 실패하면 `result.json` 에 실패 단계를 기록하고 중단한다. 실패한 날은 건너뛴다. 불완전한 영상을 올리는 것보다 낫다.

## 8. 리스크

### 8.1 API 감사 — 검증 필요

감사를 받지 않은 Google Cloud 프로젝트의 업로드는 비공개로 잠길 수 있다. 1차 구현에서 실제 업로드 1건으로 확인한다.

- 정상 동작하면 그대로 진행
- 잠기면 (a) API 감사 신청, 또는 (b) 업로드만 자동화하고 공개 전환은 수동

이 검증 전까지 예약 공개 자동화는 확정이 아니다.

### 8.2 유튜브 수익화 정책

2025년 7월부터 대량 생산된 반복 콘텐츠는 수익화 부적격 판정 대상이다. 사람 검토 없이 매일 자동 생성하는 구조는 이 정책의 위험 구간에 있다.

코드로 할 수 있는 완화책은 요일별 포맷 분리, 실제 이슈 기반 제작, 앵글 다양화까지다. 나머지는 운영 문제다. **주 1회 정도는 직접 확인하기를 권한다.** 이것은 설계로 제거할 수 없는 리스크이며, 사용자가 감수 여부를 판단할 사항이다.

### 8.3 합성 콘텐츠 고지

AI 생성 음성이 들어가므로 고지 의무 대상이다. `videos.insert` 로 설정 가능한지 1차 구현에서 확인하고, 불가하면 YouTube 스튜디오에서 채널 기본값으로 켠다.

### 8.4 사실 오류

완전 자동 발행이므로 대본의 사실 오류가 걸러지지 않는다. 완화책은 `sources` URL 강제와 수치 생성 금지 프롬프트다. 완전히 막을 수는 없다.

## 9. 검증

| 단계 | 검증 |
|---|---|
| collect | 소스별 파서를 고정 픽스처로 단위 테스트. 점수 함수는 경계값 테스트 |
| script | JSON 스키마 검증 + 글자 수 목표 범위 assert |
| voice | mp3 길이가 목표 초수 ±15% 이내 assert |
| render | ffprobe로 해상도 1080×1920 / fps 30 / 길이 검증. 프레임 3장 추출해 한글 렌더링 육안 확인 |
| upload | `--dry-run` 으로 업로드 없이 요청 바디만 출력 |
| 전체 | `python daily.py --dry-run --date 2026-09-12` |

한글 두부 문제는 자동 검증이 어렵다. 렌더 단계에서 폰트 로드를 명시적으로 검사하고, 실패 시 예외로 중단하는 것으로 대신한다.
